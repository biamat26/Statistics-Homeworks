Ex. 1 — Welford's recurrence formulas

Data x1, x2, … arrive one at a time (for instance the scores of a hacker, system after system). We want the mean and the variance of the first k values after each new value, without storing the data and without going through them twice. Notation:

$$M_k = \frac{1}{k}\sum_{i=1}^{k} x_i, \qquad SS_k = \sum_{i=1}^{k} (x_i - M_k)^2, \qquad s_k^2 = \frac{SS_k}{k-1}.$$

Step 1: Knuth's recurrence for the mean

Separate the last term of the sum and rewrite the sum of the first k − 1 values through the previous mean:

$$k\,M_k = \sum_{i=1}^{k-1} x_i + x_k = (k-1)\,M_{k-1} + x_k = k\,M_{k-1} + (x_k - M_{k-1}).$$

Dividing by k:

$$M_k = M_{k-1} + \frac{x_k - M_{k-1}}{k}, \qquad M_0 = 0.$$

The new mean is the old mean corrected by a fraction 1/k of the “surprise” δk = xk − Mk−1. We will use δk throughout, so Mk = Mk−1 + δk/k.

Step 2: the same idea for the sum of squares

Expand the square in SSk; since Σi xi = kMk:

$$SS_k = \sum_{i=1}^{k} x_i^2 - 2M_k\sum_{i=1}^{k} x_i + k M_k^2 = \sum_{i=1}^{k} x_i^2 - k M_k^2 .$$

Write the same expression for k − 1 and subtract, so that all the old squares cancel:

$$SS_k - SS_{k-1} = x_k^2 - k M_k^2 + (k-1) M_{k-1}^2 .$$

Now express everything through Mk−1 and δk, using xk = Mk−1 + δk and Mk = Mk−1 + δk/k:

$$x_k^2 = M_{k-1}^2 + 2M_{k-1}\delta_k + \delta_k^2, \qquad k M_k^2 = k M_{k-1}^2 + 2 M_{k-1}\delta_k + \frac{\delta_k^2}{k}.$$

Substituting, the terms in Mk−1 cancel and only δk survives:

$$SS_k - SS_{k-1} = \delta_k^2 - \frac{\delta_k^2}{k} = \frac{k-1}{k}\,\delta_k^2 .$$

Finally, notice that xk − Mk = δk − δk/k = (k − 1)δk/k, so the increment is a product of the deviations from the old and the new mean:

$$SS_k = SS_{k-1} + (x_k - M_{k-1})(x_k - M_k), \qquad SS_0 = 0.$$

Step 3: the variance

Dividing the recurrence for SS by k − 1 (for k ≥ 2) gives a recurrence for the sample variance directly:

$$s_k^2 = \frac{k-2}{k-1}\,s_{k-1}^2 + \frac{(x_k - M_{k-1})^2}{k}, \qquad s_1^2 = 0 .$$

and, dividing by k, for the population (biased) variance σ̂k² = SSk/k:

$$\hat\sigma_k^2 = \frac{k-1}{k}\,\hat\sigma_{k-1}^2 + \frac{k-1}{k^2}\,(x_k - M_{k-1})^2 .$$

In practice one keeps SSk and divides only when the variance is needed: it is simpler and avoids repeated rounding.

The code

The core of the algorithm is three lines per new value:

// state: k = count, M = mean, SS = sum of squared deviations (all start at 0)
k += 1;
const d = x - M;          // δ = x − M(k−1)
M  += d / k;              // Knuth:   M(k)  = M(k−1)  + δ / k
SS += d * (x - M);        // Welford: SS(k) = SS(k−1) + (x − M(k−1))(x − M(k))
// sample variance s² = SS / (k − 1),  population variance = SS / k

The same in Python, as a small reusable class:

class Welford:
    def __init__(self): self.k, self.M, self.SS = 0, 0.0, 0.0
    def add(self, x):
        self.k += 1; d = x - self.M
        self.M += d / self.k
        self.SS += d * (x - self.M)
    def var(self): return self.SS / (self.k - 1) if self.k > 1 else 0.0

Step by step

Why not the textbook formula?

The one-pass “computational formula” $s^2 = \frac{1}{k-1}\left(\sum x_i^2 - \frac{(\sum x_i)^2}{k}\right)$ also needs no second pass, but it subtracts two huge, almost equal numbers. In floating point (about 16 significant digits) the difference loses all its precision: catastrophic cancellation. Welford's recurrence only ever works with deviations from the current mean, which are small.

Ex. 2 — Sampling mean and sampling variance

We extend Homework 3: each penetration attempt now gets a score between 0 and 10, drawn from a fixed distribution with mean μ and variance σ². There are m hackers, each attacking n systems, so every hacker produces a trajectory of n i.i.d. scores. For each hacker j, Welford's recurrences give the sampling mean and the sampling variance of its n scores:

$$\bar X^{(j)} = \frac{1}{n}\sum_{i=1}^{n} X_i^{(j)}, \qquad S^{2\,(j)} = \frac{1}{n-1}\sum_{i=1}^{n}\bigl(X_i^{(j)} - \bar X^{(j)}\bigr)^2, \qquad j = 1,\dots,m .$$

Across hackers we average them and compare with μ and σ². Theory says:

$$E[\bar X] = \mu,\quad \operatorname{Var}(\bar X) = \frac{\sigma^2}{n}; \qquad E[S^2] = \sigma^2,\quad \operatorname{Var}(S^2) = \frac{\mu_4}{n} - \frac{\sigma^4 (n-3)}{n(n-1)},$$

where μ4 = E[(X − μ)⁴] is the fourth central moment. Dividing by n instead of n − 1 would give E = σ²(n − 1)/n: a biased estimator.

Conclusions

  • The sampling mean and the sampling variance are unbiased. For every n, the average over the m hackers of X̄ matches μ and the average of S² matches σ², up to Monte Carlo noise of order 1/√m. This is the meaning of E[X̄] = μ and E[S²] = σ²: individual hackers can be far off, but there is no systematic error.
  • Dividing by n − 1 matters. The deviations are measured from X̄, which is itself fitted to the data, so they are on average smaller than the deviations from μ: one degree of freedom is “used” by the mean. SS/n underestimates σ² by the factor (n − 1)/n, which is visible for small n (−50% at n = 2) and vanishes as n grows. Dividing by n − 1 (Bessel's correction) removes the bias exactly.
  • More systems per hacker, less variability. Var(X̄) = σ²/n and Var(S²) ≈ (μ4 − σ⁴)/n both decrease as 1/n: the standard deviation of each estimate shrinks as 1/√n. Quadrupling the number of systems halves the spread of the estimates. Both estimators are therefore consistent: they converge to μ and σ² as n → ∞ (Law of Large Numbers).
  • The shape of the sampling distributions. X̄ is approximately normal already for moderate n (CLT). S² converges more slowly: for small n its distribution is clearly skewed to the right, especially for skewed or heavy-tailed scores (large μ4, e.g. the bimodal distribution), and it can never be negative.
  • Why this is useful in inferential statistics. In practice we observe one sample (one hacker, or one audit of n systems) and μ, σ² are unknown. These results say how much to trust it: X̄ estimates μ with standard error σ/√n, estimated by S/√n, which gives confidence intervals such as X̄ ± 1.96·S/√n and the t-test. Unbiasedness and the known variance of the estimators are what make such statements possible; the m simulated hackers are just a way of seeing the sampling distribution that, in a real study, we never observe directly.
  • n and m play different roles. n is the sample size of each estimate and controls its precision; m is the number of repetitions of the whole experiment and only controls how well we can see the sampling distribution (the averages across hackers have standard error σ/√(nm) and √(Var(S²)/m)).
  • Welford's recurrences make all this cheap and safe. One pass, O(1) memory per hacker, numerically stable: suitable for streams of scores that are never stored.
