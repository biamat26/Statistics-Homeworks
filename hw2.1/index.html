Toy ECC Encryption vs. the Caesar Cipher

Encrypting the same message with a toy elliptic-curve scheme on secp256k1 and with the Caesar cipher, comparing their keys and statistics, and breaking both: the Caesar cipher by statistical cryptanalysis, the toy scheme by searching its restricted key space.

1. Encryption with the toy scheme on secp256k1

In Homework 1 we computed public keys Q = d·G on secp256k1. Elliptic curves do not encrypt directly: the standard way to encrypt with them is to use the curve for a key agreement (Diffie–Hellman) and then a symmetric cipher for the data. Our toy scheme is a simplified version of ECIES (Elliptic Curve Integrated Encryption Scheme), with the private key restricted to a small range so that it can be attacked in section 5.

Key generation (receiver)

Choose the private key d at random in [1, 2B] (a real wallet would use [1, n−1], n ≈ 2²⁵⁶).
Publish the public key Q = d·G.

Encryption (sender, knows Q)

1. Pick a fresh random ephemeral key r ∈ [1, n−1].
2. Compute R = r·G and the shared secret S = r·Q.
3. Derive a keystream K = SHA-256(S.x ‖ 0) ‖ SHA-256(S.x ‖ 1) ‖ …
4. Ciphertext: (R, c = m ⊕ K).

Decryption (receiver, knows d)

1. Compute S = d·R.
2. Same keystream K from S.x.
3. Plaintext: m = c ⊕ K.

It works because both sides reach the same point: d·R = d·(r·G) = r·(d·G) = r·Q = S. An eavesdropper sees Q and R but not d or r, and computing S from them is the Diffie–Hellman problem on the curve.

2. The Caesar cipher

Every letter is shifted by a fixed number of positions k in the alphabet; other characters are left unchanged. With letters numbered a = 0, …, z = 25:

Ek(x) = (x + k) mod 26     Dk(y) = (y − k) mod 26

The same secret k is used to encrypt and to decrypt (symmetric cipher). There are only 26 keys, and k = 0 does nothing.

4. Statistical cryptanalysis of the Caesar cipher

A Caesar cipher only permutes the alphabet cyclically, so the ciphertext keeps the letter statistics of the language, just rotated. If we know what English “looks like”, we can find the rotation that makes the ciphertext look most like English.

The reference model: a corpus of English

Five ways to score a key

Let c be the ciphertext, n its number of letters, Oj the count of letter j in c and pi the English frequency of letter i. For every candidate key k = 0, …, 25:

MethodScore of key kBestIdea
Most frequent letterO(4+k) mod 26maxThe most common ciphertext letter must be the encryption of “e”.
χ² statisticΣi (O(i+k) mod 26 − n·pi)² / (n·pi)minGoodness of fit of the whole histogram to English.
CorrelationΣi pi · O(i+k) mod 26 / nmaxInner product of the two distributions (≈ 0.065 for the right key, ≈ 0.038 for a random one).
Bigram log-likelihoodΣt log₁₀ P(mt mt+1)maxDecrypt with k and measure how likely the pairs of letters are in English.
Trigram log-likelihoodΣt log₁₀ P(mt mt+1 mt+2)maxSame with triples (“the”, “ing”, “and”…): uses word structure, not only letter counts.

Methods 2–5 are an exhaustive key search (only 26 keys) combined with a statistical scoring function that recognises the right plaintext automatically. Without a score, exhaustive search would need a human to read 26 candidate texts. P(·) are estimated from the corpus, with add-½ smoothing for n-grams that never occur.

Break a ciphertext

How much ciphertext is needed?

For each length, many random excerpts of the held-out test book are encrypted with a random key (1–25) and every method tries to recover it.

Effectiveness and limitations

  • Very effective on normal text. With the trigram score a dozen letters are almost always enough; χ² and correlation need about 30–50 letters; “most frequent = e” is unreliable even with a few hundred letters, because it uses a single number instead of the whole distribution.
  • Short messages are the main limit. With 3–5 letters several keys produce plausible strings (“yes”, “ifc”, “Xjv”…) and the statistics cannot separate them: the answer is a ranking, not a certainty.
  • The model must match the text. Frequency methods assume “typical” English. A text that avoids the letter e defeats “most frequent = e” but not χ² or n-grams, which use all the letters. Other languages still often work for χ² (Italian and English share many frequent letters) but less reliably; random codes, abbreviations or numbers carry no language statistics and cannot be broken this way.
  • Exhaustive search is cheap but blind. Trying 26 keys is instant; the statistics are what turn it into an automatic attack. N-gram scoring is the most powerful because it uses the dependence between neighbouring letters, i.e. more information per ciphertext letter.
  • It generalises. The same idea (score candidate plaintexts with a language model) breaks substitution and Vigenère ciphers, where the key space is too large to try every key without guidance.

5. Breaking the toy ECC scheme: searching the restricted key space

The attacker sees the public key Q and the ciphertext (R, c). Statistics are useless here: the bytes of c are uniform. But the toy scheme picks d in [1, 2B], so the attacker can simply look for the d with d·G = Q. Once d is found, decryption is immediate: S = d·R.

Exhaustive search

Compute G, 2G, 3G, … (one point addition per step) until the result equals Q.
Cost: up to 2B additions, 2B−1 on average. Memory: O(1).

Baby-step giant-step (Shanks, 1971)

Write d = i·m + j with m = ⌈√2B⌉. Store x(j·G) for j = 1…m (baby steps), then compute Q − i·(mG) for i = 1, 2, … (giant steps) until it is in the table.
Cost: about 2·2B/2 additions. Memory: 2B/2 points.

Cost as the key grows

Why this does not work against real ECC

  • A properly generated secp256k1 key is uniform in [1, n−1] with n ≈ 2²⁵⁶. Exhaustive search needs about 2²⁵⁵ point additions; the best generic algorithms (baby-step giant-step, Pollard's rho) still need about √n ≈ 2¹²⁸.
  • 2¹²⁸ ≈ 3.4·10³⁸ operations: even with a billion computers doing a billion additions per second each, it would take about 10¹³ years, roughly a thousand times the age of the universe. Baby-step giant-step would also need 2¹²⁸ stored points, far more than all the storage on Earth.
  • secp256k1 has prime order and no known special structure that gives faster attacks (Pohlig–Hellman needs a composite order; MOV/anomalous attacks need special curves). The security of ECC rests on the size of the key space together with the hardness of the ECDLP.

6. Other attacks and weaknesses of the toy design

Not every weakness of the toy scheme comes from the small key. Some come from how it is built.

Reusing the ephemeral key r

If two messages are encrypted with the same r, they share the same keystream K and c₁ ⊕ c₂ = m₁ ⊕ m₂: knowing (or guessing) one message reveals the other, with no need to know d.

Malleability: no integrity protection

There is no MAC, so the ciphertext can be modified. If an attacker knows part of the message, XOR-ing c with (old ⊕ new) changes it in a predictable way, and the receiver decrypts the forged text without noticing.
